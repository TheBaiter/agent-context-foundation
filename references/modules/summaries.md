# Summaries Module

Read when a complex area is repeatedly reconstructed from many files.

Create a summary only when it saves meaningful future discovery.

A useful summary states:

- when to read,
- when not to read,
- canonical owners,
- main entrypoints or symbols,
- stable contracts or invariants,
- known risks,
- exact verification route,
- freshness anchors.

Do not summarize code that is already easy to understand locally. Prefer a local README when the knowledge belongs to one component or subtree. Use an agent-only summary for cross-cutting context.
