# Migration Module

Read when compacting or migrating existing agent documentation or memory.

## Process

1. Identify active instruction entrypoints and canonical owners.
2. Inventory duplicate, stale, contradictory, and low-value content.
3. Classify each item as durable guidance, current state, task history, observation, or error knowledge.
4. Keep durable verified guidance with one owner.
5. Move task chronology to the project task system when it still matters.
6. Route instead of duplicate.
7. Retire obsolete paths only after active references are updated.
8. Do not create modules just to mirror the old structure.
9. Validate that the new default read is smaller and that important anchors were not lost.

Migration is successful when future tasks need less irrelevant context without losing decision-critical information.
